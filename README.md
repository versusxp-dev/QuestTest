# QuestTest - Текстовая приключенческая игра

**Версия:** 1.1 (Engine + Cartridge Architecture)

Текстовая приключенческая игра с ASCII-графикой и интерактивным меню. Погрузитесь в атмосферное путешествие через заброшенные комнаты, тёмные коридоры и загадочные локации.

## 🎯 Архитектура 1.1: Движок + Картридж

Начиная с версии 1.1, проект использует профессиональную архитектуру разделения кода и контента:

- **Движок (Engine)**: `main.py`, `renderer.py` — интерпретатор, который загружает и исполняет сценарий
- **Картридж (Cartridge)**: `scenario.json` — файл с сюжетом, локациями, текстами и переходами
- **Ресурсы (Assets)**: `assets.py` — библиотека ASCII-артов и описаний для локаций

Это позволяет создавать новые игры, просто меняя `scenario.json`, без изменения кода движка.

### Что изменилось в версии 1.1

- ✅ **Удалён `logic.py`**: Вся логика обработки действий перенесена в движок (`main.py`)
- ✅ **Интеграция с assets.py**: Движок теперь использует ASCII-арты и описания из `assets.py`
- ✅ **Исправлено дублирование кода**: Убран дублирующий метод `load_scenario()`
- ✅ **Улучшена навигация**: Корректная обработка навигации при переменном количестве опций (до 5 максимум)
- ✅ **Маппинг art_id**: Автоматическое сопоставление идентификаторов артов между `scenario.json` и `assets.py`

## 🎮 Особенности

- **ASCII-графика**: Визуальное оформление сцен с помощью символов и эмодзи
- **Интерактивное меню**: Навигация с помощью цифр (1-5) или стрелок вверх/вниз
- **Система состояний**: Сохранение прогресса, инвентарь и флаги сюжета
- **Динамические опции**: Меню адаптируется под количество доступных действий (максимум 5)
- **Условные действия**: Поддержка `require_flag` и `require_no_flag` для отображения действий
- **Адаптивный рендеринг**: Корректное отображение на терминалах любого размера

## 🗺️ Локации (из scenario.json)

- **main_menu** - Главное меню с приветствием и выбором начала игры
- **room_start** - Стартовая комната с картой на стене и выходом в коридор
- **corridor** - Тёмный коридор с тупиком и блестящим предметом на полу

## ⚙️ Технические детали

### Рендеринг

Игра использует фиксированный холст 100×40 символов, разделённый на зоны:
- **Зона изображения** (12 строк) - ASCII-арт локации
- **Зона текста** (12 строк) - Описание ситуации  
- **Зона меню** (10 строк) - до 5 пунктов выбора (адаптивно под количество действий)

### Обработка эмодзи

Модуль `wcwidth` обеспечивает корректный расчёт ширины символов, включая эмодзи и специальные Unicode-символы.

### Система флагов

Движок поддерживает систему флагов для управления состоянием игры:
- `set_flag`: Установить флаг после выполнения действия
- `require_flag`: Показать действие только если флаг установлен
- `require_no_flag`: Показать действие только если флаг НЕ установлен

Пример использования в `scenario.json`:
```json
{
  "text": "Обыскать тумбочку",
  "target": "room_start",
  "set_flag": "has_key",
  "require_no_flag": "has_key"
}
```

## 🛠️ Разработка

### Добавление новой локации в scenario.json

Просто добавьте новую секцию в `scenario.json`:

```json
"new_location": {
  "art_id": "название_арта",
  "text": "Описание новой локации",
  "actions": [
    {"text": "Действие 1", "target": "другая_локация"},
    {"text": "Действие 2", "target": "ещё_одна_локация"}
  ]
}
```

Затем добавьте соответствующий ASCII-арт и описание в `assets.py`:
```python
ASCII_ART["название_арта"] = """ваш арт"""
SCENE_DESCRIPTIONS["название_арта"] = ["описание", "строки"]
```

### Маппинг идентификаторов

В версии 1.1 `art_id` из `scenario.json` напрямую сопоставляется с ключами в `assets.py`. Если имена отличаются, используйте одинаковые идентификаторы в обоих файлах:

```python
# scenario.json
{
  "room_start": {
    "art_id": "room",  # Должен совпадать с ключом в ASCII_ART
    ...
  }
}
```

```python
# assets.py
ASCII_ART = {
    "room": """...ваш арт...""",
    ...
}
```

### Создание нового сценария (картриджа)

Скопируйте `scenario.json` и измените его содержимое — движок автоматически загрузит новый сюжет без изменения кода.
